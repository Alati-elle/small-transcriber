# Известные проблемы

Статус на 23 сентября 2026 года. Ни одна из перечисленных проблем не исправлялась при baseline-консолидации.

## P0 — секрет и текст встречи видны в process list

Python-скрипты передают API key в аргументе `curl -H`, а JSON body — в `curl -d`. На macOS эти значения видны в `ps -ww`. Для генератора протокола payload содержит текст встречи; при транскрипции видны ключ, file URI и словарный контекст.

Проверка выполнена синтетическим curl-процессом с фиктивными значениями. Реальный ключ и реальный текст встречи не выводились.

Предлагаемое отдельное изменение: сохранить `curl -4`, передавать JSON через stdin (`--data-binary @-`), а заголовок с ключом — через pipe/file descriptor либо временный файл с режимом `0600`. Это изменение требует отдельного review и regression-проверки.

## P1 — неуспешный повторный анализ удаляет прежний протокол

Перед запуском этапа протокола GUI удаляет существующие `*_ПРОТОКОЛ.json` и `*_ПРОТОКОЛ.html`. Если новый запрос завершится ошибкой, прежний успешный результат будет потерян.

Предлагаемое изменение: генерировать во временные файлы и атомарно заменять предыдущий протокол только после успешной проверки обоих результатов.

Ограничение реализации в source-ветке: JSON и HTML публикуются отдельными атомарными `os.replace`. При обычной ошибке между заменами выполняется rollback, однако принудительное завершение процесса или сбой ОС ровно между двумя `os.replace` теоретически может оставить JSON и HTML разных версий. Полная атомарность пары потребовала бы публикации через versioned directory и один atomic pointer/swap; пока она не реализована. Production остаётся на прежней версии.

## P1 — cache не связан с содержимым исходного аудио

Chunks и Gemini JSON повторно используются по ожидаемому имени и базовой проверке содержимого JSON. Digest, размер и mtime исходного аудио в cache manifest не фиксируются.

Замена аудио другим файлом с тем же путём и stem может привести к использованию stale cache.

Предлагаемое изменение: manifest с SHA-256 исходника, параметрами chunk/overlap и моделью; при material drift — не использовать cache автоматически.

## P1 — подпись приложения невалидна

Текущая `Расшифровать встречу.app` имеет ad-hoc signature, но `codesign --verify --deep --strict` сообщает изменённый `main.scpt` и добавленный backup-файл внутри bundle. `gemini_meeting_gui` не подписан.

На текущем Mac приложение запускается, однако переносимость и будущие проверки Gatekeeper не гарантированы. Исправление codesign отложено.

## P1 — права на результаты

Проверенные TXT и Gemini JSON имеют режим `0644`, а домашний каталог — `0755`. Другой локальный пользователь потенциально может прочитать материалы встречи, если права родительских каталогов это допускают.

Предлагаемое изменение: приватный umask или явные права `0600` для файлов и `0700` для каталогов результата. Изменение требует проверки совместимости с Finder и текущим workflow.

## P2 — сетевые ошибки не используют fallback моделей

Fallback протокола действует для HTTP JSON с кодами 429/503. Ошибки самого curl — DNS, connect error или timeout — выбрасываются до перехода к следующей модели.

Последний найденный запуск 23 сентября завершился после 300-секундного timeout и `Could not resolve host`.

## P2 — у транскриптора нет отдельной обработки 503

Транскриптор специально обрабатывает только 429. Ответ 503 приводит к общей ошибке Gemini без задержек и fallback; при этом транскрипция использует одну модель.

## P2 — общий launcher log в `/tmp`

Все launcher-процессы используют `/tmp/gemini_meeting_gui.log` с перенаправлением `>`. Параллельные запуски могут перезаписывать общий файл.

## P2 — возможна гонка для одинакового output path

AppleScript запускает отдельный GUI для каждого перетащенного файла. Два одновременно обработанных файла с одинаковым stem в одной папке используют один output directory и одинаковые логи/результаты.

## P2 — папка открывается до окончания полного pipeline

Транскриптор вызывает `/usr/bin/open <outputDir>` сразу после создания TXT. GUI в этот момент ещё только переходит к созданию протокола. Это не ошибка данных, но поведение расходится с формулировкой «открыть результат после завершения».

## P2 — жёстко заданные пути инструментов

Используются `/usr/bin/python3`, `/usr/local/bin/ffmpeg` и `/usr/local/bin/ffprobe`. Перенос на Mac с Homebrew в `/opt/homebrew` или без системного Python потребует изменения конфигурации.

## P2 — отсутствует безопасный репозиторный regression fixture

Существующие контрольные данные содержат реальные встречи. Они сознательно не скопированы в source tree. Для автоматического regression-теста нужен синтетический или обезличенный fixture.

## Ограничения распознавания

- diarization выполняется независимо для chunks, поэтому один человек может получить несколько speaker ID;
- нормализация speaker ID является модельным выводом и может ошибаться;
- имя присваивается только при найденных текстовых основаниях, но качество зависит от расшифровки;
- overlap merge может сохранить дубли, если безопасное совпадение не найдено; это предпочтено потенциальной потере речи;
- текущий pipeline ориентирован на русский язык (`ru-RU`).

## 429 и квоты

Транскриптор распознаёт дневную квоту и останавливается, сохраняя готовые chunks. Для остальных 429 используются повторы. Генератор протокола после повторного 429 переключает модель, но общий лимит API key может затронуть всю цепочку.

## 503 и перегрузка моделей

Генератор делает два повтора текущей модели через 10 и 30 секунд и после третьего 503 переключается на следующую модель. Это реализовано отдельно в трёх местах, поэтому будущие изменения нужно синхронизировать.

## VPN, IPv4 и геолокация

После ошибки `User location is not supported for the API use` во все актуальные curl-вызовы добавлен `-4`. Изменять или убирать его без отдельного сетевого теста нельзя. DNS/VPN-сбой всё ещё способен прервать pipeline.
